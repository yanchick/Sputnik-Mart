# ADR-0003 — Живой поток для базового уровня: SSE

- **Дата:** 2026-09-07
- **Статус:** Принят

## Контекст

ТЗ §5.4: `GET /api/v1/streams/{subscriptionId}` — живой поток чтений подписчику.
§13: выбрать транспорт для базового уровня между **SSE** и **WebSocket**.

- WebSocket: полнодуплекс, сложнее на клиенте (SPA) и в карусели курса, нужен
  отдельный протокол/заголовки auth.
- SSE: one-way сервер→клиент на обычном HTTP, автоматически переподключается,
  тривиален для демо-графика в витрине и в ноутбуках.

## Решение

Базовый уровень (профиль `base`/`adv`) отдаёт живой поток как **Server-Sent
Events** (`text/event-stream`) на `/api/v1/streams/{subscriptionId}`.

Формат события (datascience-дружелюбный, idempotent по `readingId`):

```text
event: reading
id: rd_9f2c
data: {"readingId":"rd_9f2c","stationId":"st_metro-01","metric":"TEMPERATURE",
       "value":18.4,"unit":"C","measuredAt":"2026-09-07T12:34:56Z"}

event: ping
data: {"t":1715000000000}
```

## Последствия

- Профиль `adv` может оставить WebSocket как продвинутую практику, но
  контракт по умолчанию — SSE (задокументирован в `openapi-delivery.yaml`).
- Клиентская часть (Panel) и блокноты получают единый механизм подписки.
- Открытый вопрос SSE-контракта закрыт; описание переносится в спеки.
