# ADR-0002 — Генераторы фейковых данных: пакет `sim` с CLI

- **Дата:** 2026-09-07
- **Статус:** Принят

## Контекст

ТЗ (§6) требует детерминированных генераторов с профилями «чистоты» и
конфигурируемым объёмом. §13: реализовать ли генераторы **отдельным Python-пакетом
с CLI** (`python -m sim.sensors --seed 42`) или **инлайн-скриптами** внутри сервисов.

Инлайн-скрипты проще на старте, но дублируются между `sensor-gateway`,
`catalog-service`, `sim-buyers` и практиками очистки; их сложно переиспользовать
студентам вне docker-compose.

## Решение

Отдельный Python-пакет `sim` (модуль верхнего уровня репозитория) с единым CLI:

```bash
python -m sim.sensors    --seed 42 --stations 50 --interval 60 --hours 720
python -m sim.providers  --seed 7  --providers 5 --rows 1_000_000
python -m sim.buyers     --seed 11 --users 300
python -m sim.dirty      --layer bronze --miss 0.03 --dup 0.01 --outlier 0.005
```

- Пакет устанавливается в контейнеры сервисов и студенческие ноутбуки.
- Один API генерации (seed + параметры объёма/чистоты) → единый формат данных.
- Модули переиспользуются и в практиках очистки/валидации (§6 ключевой сценарий).

## Последствия

- Немного больше инфраструктуры на старте (упаковка, зависимости).
- Детерминированность проверяемая: фикс. `seed` → совпадающий дайджест выдачи,
  что используется в приёмке (§11).
- `sim-dirty` намеренно «портит» слой; это отдельный флаг, чтобы не портить
  данные при обычном прогоне.
