# ADR-0006 — Фронтенд фасада: Python + Panel

- **Дата:** 2026-09-18
- **Статус:** Принят

## Контекст

Реестр сервисов (§3 ТЗ) объявлял `web-vitrina` как «SPA (React/Vue, nginx)», оставляя
реальный стек фасада неопределённым. Нужно выбрать между **JS-SPA** (React + Vite +
TypeScript) и **Python data-app** (Panel/HoloViz или Dash). Выбор влияет на toolchain
CI, язык, на котором читается курс, и скорость сборки демо-портала.

Требования к фасаду: витрина каталога, карточка датасета, личный кабинет, живой график
по подписке (SSE), Quality-page, docs. Пользователь — студент базового уровня; сборку
поддерживают авторы курса.

## Решение

`web-vitrina` реализуется на **Panel (HoloViz) поверх Bokeh-сервера**, на том же
Python-стеке, что и backend (§1.1 ТЗ). Компоненты: `panel` (FastListTemplate),
`Tabulator` (таблицы), `hvPlot`/`ECharts` (графики), `param` (состояние),
`panel.auth` (вход), `httpx` + `httpx-sse` (REST и SSE). Фасад общается **только**
с `api-gateway`.

Отклонены альтернативы:

- **React + Vite + TypeScript** — индустриальный стандарт, но добавляет второй
  toolchain (Node, сборка, дублирование типов) без учебной выгоды для курса по
  инженерии данных; тот же результат достигается меньшей ценой.
- **Dash (Plotly)** — Plotly-центричен, менее гибок в кастомной вёрстке витрины.

## Последствия

- Единый язык на всём стеке: сервисы, пайплайны, генераторы, фронт, ноутбуки студентов.
- В CI нет отдельной JS-сборки — контракты и тесты Python остаются единственным гейтом.
- Таблицы, графики и DataFrame-представления нативные; время до рабочего портала короче.
- SSE читается серверной стороной (`httpx-sse`) и пушится в Bokeh-виджет живого графика.
- Фасад остаётся **заменяемым**: React-клиент можно добавить позже отдельным сервисом,
  не меняя остальные сервисы и `specs/*.yaml` (общение только через gateway).
- Обновлены: §1.1 и §3 ТЗ, реестр сервисов, паспорт `web-vitrina`,
  [[ADR-0003 — Живой поток SSE]] (формулировка «клиент React» → клиент Panel).
