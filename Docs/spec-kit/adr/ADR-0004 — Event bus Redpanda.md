# ADR-0004 — Шина событий: Redpanda (основная) + NATS JetStream (опционально)

- **Дата:** 2026-09-07
- **Статус:** Принят

## Контекст

ТЗ §3: `event-bus` = **Redpanda (Kafka-совместимая) + NATS JetStream**. Две шины
в одном учебном стеке добавляют вес (память, конфигурация). Надо решить, обе ли
обязательны, либо одна основная.

- Redpanda: Kafka-API, топики `commerce.*` и `sensors.readings`, DLQ-топики;
  полностью покрывает асинхронные нити курса (Kafka — ключевая тема).
- NATS JetStream: проще, лёгкий; полезен для продвинутой практики сравнения, но
  не обязателен для сквозного сценария.

## Решение

**Redpanda — обязательная шина** по умолчанию во всех профилях (`adv`, `demo`).
NATS JetStream **не включается** в базовую поставку; остаётся как опциональный
`profile`/флаг для продвинутой практики сравнения шин.

Контракты событий объявляются один раз (AsyncAPI) и не зависят от конкретной шины.

## Последствия

- Меньше сервисов в docker-compose по умолчанию → легче запуск на студенческих машинах.
- Все топики (`commerce.*`, `sensors.readings`, DLQ) живут на Redpanda.
- NATS-практика выносится отдельным разделом продвинутого уровня, не блокируя M2–M4.
