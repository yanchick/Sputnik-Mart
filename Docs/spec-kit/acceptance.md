# Критерии приёмки (по сервисам)

Сквозные критерии из §11 ТЗ разложены по сервисам. Сервис «принят», когда
закрыты **все** его чек-боксы. Контракт-источник — `specs/*.yaml` ([[README]]).

## Глобальные критерии (применяются ко всем)

- [ ] Контракт API/событий соответствует спецификации (OpenAPI/AsyncAPI валидны, CI зелёный).
- [ ] Эндпоинты отдают задокументированные коды и стандартные ошибки ([[contracts/api-conventions]]).
- [ ] Генераторы детерминированны при фиксированном `seed`.
- [ ] Сквозной сценарий (§10 ТЗ) проходит от события до метрики/графика.
- [ ] Повторный запуск DAGа не создаёт дублей (идемпотентность).
- [ ] Запускается одной командой `docker compose --profile <base|adv|demo> up`.
- [ ] Observability: лаг топика, свежесть витрины, алерты при деградации.

## По сервисам

### api-gateway
- [ ] Маршрутизация на все бэкенд-сервисы; Swagger/OpenAPI UI.
- [ ] Auth (Bearer), rate-limit с заголовками `X-RateLimit-*`.
- [ ] `requestId` генерируется на входе и прокидывается вниз по цепочке.
- [ ] Единый формат ошибок и `requestId` в каждом ответе об ошибке.

### identity-service
- [ ] `POST /api/v1/auth/login` выдаёт токен; `/users/me` возвращает покупателя.
- [ ] Выпуск API-ключей; маскирование PII (email/телефон) в любых выгрузках.

### catalog-service
- [ ] Каталог: пагинация, фильтры `category`, `minQuality`; карточка и `schema`.
- [ ] `sample` отдаётся в CSV/JSON/Parquet по запросу.
- [ ] `qualityScore` согласован с Quality-page (см. validation-service).

### order-service
- [ ] Заказ и подписка создаются; события `commerce.orders`/`.subscriptions` в Kafka.
- [ ] Список заказов покупателя корректен; повторная попытка не дублирует (идемпотентность).

### delivery-service
- [ ] `download` доступен только при купленном датасете (иначе 403).
- [ ] SSE-поток `/streams/{subscriptionId}` отдаёт свежие чтения (см. [[adr/ADR-0003 — Живой поток SSE]]).
- [ ] Лимиты выгрузки соблюдаются.

### review-service
- [ ] Отзывы о качестве; события `commerce.reviews` с тональностью в NLP-корпус.

### content-нить (sensor-gateway → … → gold)
- [ ] `sensor-gateway` принимает чтения и публикует в `sensors.readings.v1`.
- [ ] `ingestion-service`: Kafka → MinIO bronze; битые записи → DLQ.
- [ ] `validation-service`: bronze → silver без дублей/пропусков; отчёт качества.
- [ ] `transform-service`: silver → gold (фичи, временные ряды, сентимент).
- [ ] Сценарий `sim-dirty` → Quality-page показывает деградацию → восстановление после чистки.

### orchestration (Airflow)
- [ ] DAGи из §8 ТЗ выполняются идемпотентно (`retries`+backoff, сенсоры свежести).
- [ ] Сквозной прогон подписки завершается доставкой свежих чтений на API.

### observability
- [ ] Метрики лага/свежести доступны в Grafana; алерт срабатывает при деградации.
