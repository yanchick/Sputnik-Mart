# Контракты данных, генераторы и слои

Общие схемы, требования к генераторам фейковых данных и модель слоёв.
Источник требований — [[../../ТЗ — Демо-портал маркетплейса данных (SDD)]] §4, §6, §7.

## Общие правила полей

- camelCase; `id` вида `{prefix}_{...}`; временные метки UTC ISO-8601; float64.

## 1. Продукт (каталог)

```jsonc
{
  "datasetId": "ds_weather-stations",
  "providerId": "pv_metro",
  "name": "Метеостанции города",
  "category": "WEATHER",
  "schema": { "fields": [ { "name": "temperature", "type": "DOUBLE", "unit": "C" } ] },
  "frequencySec": 60,
  "volumeEstimate": "1.2M rows/month",
  "pricePerUnit": 1200.0,
  "qualityScore": 0.92,
  "lastUpdatedAt": "2026-09-07T12:00:00Z",
  "licence": "sputnik_edu_v1"
}
```

## 3. Генераторы (пакет `sim`, см. [[../adr/ADR-0002 — Генераторы пакет sim]])

| Модуль | Генерирует | Параметры |
| --- | --- | --- |
| `sim-sensors` | Чтения датчиков (метео, PM2.5, шум, энергия) | станции, интервал, период, seed |
| `sim-providers` | Провайдеры + партнёрские CSV-выгрузки | число провайдеров, объём |
| `sim-buyers` | Покупатели и поведение (клики/заказы/подписки/скачивания/отзывы) | пользователи, seed |
| `sim-dirty` | Контролируемое «загрязнение» слоя | доли пропусков/дублей/выбросов/битых |

Требования:

- Детерминированность: одинаковый `seed` → одинаковый датасет (проверяемо в CI).
- Профиль «чистоты» задаётся параметром (для практик очистки/валидации).
- Объём конфигурируется: от «1 станция/день» до «50 станций/месяц».

Форматы выдачи: JSON-строки в Kafka (поток) и CSV/JSON/Parquet-файлы в MinIO.

Ключевой учебный сценарий: `sim-dirty` «портит» bronze → `validation-service`
ловит и показывает на Quality-page → студент чистит и сверяет с `qualityScore`.

## 4. Слои данных и хранение

| Слой | Где | Содержимое |
| --- | --- | --- |
| bronze (сырьё) | MinIO `lake/bronze/{provider}/{dt}` | как получено от генераторов/провайдеров |
| DLQ | Kafka `sensors.readings.dlq` | битые записи |
| silver (чистый) | MinIO `lake/silver/{dataset}/{dt}` | прошло валидацию, без дублей/пропусков |
| gold (витрины) | ClickHouse | агрегаты, фичи, отдаваемые датасеты |
| Операционные | Postgres | каталог/заказы/пользователи |
| Метаданные провайдеров | MongoDB | гибкая схема |
| События commerce | Kafka | топики `commerce.*` |

Пайплайн слоёв: `bronze → validation (Pandera/GE) → silver → transform → gold`.
ClickHouse: MergeTree, партиционирование по дате, Materialized Views для метрик.
